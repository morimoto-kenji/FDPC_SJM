■■■■■ １．このドキュメントについて

　2.32SJ.M を作るにあたって調べた FD の内部構成，機種による実装の違い，各
パッチの方式，および 2.32SJ.M での実装をまとめたものです。アドレスは
COM ファイルとしてロードされたときのオフセット（ファイル位置 + 100h）です。
特に断りのない限り、2.32SJ の FD98.COM（60187 バイト）のアドレスです。


■■■■■ ２．FD 2.32SJ の構成

◆◆◆◆ FD.COM（ローダー）

	・起動時に環境変数などから FD98.COM のパス（0x3A0），COMSPEC（0x36A）
	  を求め、自分を先頭 0681h バイトに縮めて常駐する
	・FD98.COM を EXEC し、終了コードで次の動作を決める
	    0     終了
	    'C'   コマンドの実行（コマンド行は FD.COM の PSP:0080h に FD98 が
	          書き込む）→ COMSPEC で実行したあと FD98.COM を再起動
	    'V'   ウイルスチェックの警告
	    1     エラー
	・FD98.COM は外部コマンドの実行時にいったん終了するため、状態は
	  FD.COM の常駐領域（0200h～0680h）に保存し、再起動時に読み戻す
	  （FD98 側からは PSP:0016h の親 PSP を通して参照）
	・ＳＪでは FD.COM の 1100h 以降に長いファイル名用の Unicode⇔シフト JIS
	  変換表（U2SJ.LST 由来）が入っている。これは常駐せず、FD98.COM が
	  必要なときにファイルから読む

◆◆◆◆ FD98.COM（本体）

	・ＳＪは自分のファイルサイズ（0EB1Bh = 60187）と、親プロセスの
	  先頭（0103h）が "FD.COM" であることを確認する
	・DC19h 以降はオーバーレイ。起動後は作業領域として使い回すため、
	  K，D，B，I，HELP などの実行時に、自分のイメージを別セグメントに
	  複写し、FD98.COM ファイルの末尾（0DB19h～）を読み込んで、その
	  セグメントで実行する
	・FDCUST2.COM は FD.CFG を読んで、FD98.COM 内の固定位置（0E45h 付近
	  など）を書き換える

◆◆◆◆ 画面とキー（PC-98 版）

	・テキスト VRAM のセグメントは変数（ＳＪでは cs:[6897h]）で持つ。
	  通常 A000h，ハイレゾ時 E000h。属性面は +2000h
	・VRAM のセル：半角は下位バイトに文字コード，上位バイト 0。全角は
	  左セル＝(JIS 第１バイト - 20h, 第２バイト)，右セル＝左セルの下位
	  バイトに 80h を加えたもの
	・属性：bit0 ST（0 で非表示），bit1 ブリンク，bit2 リバース，bit3
	  アンダーライン，bit5～7 色（G R B）
	・主な文字列出力は 6899h（DS:DX の文字列を DI の位置に AL の属性で）
	・キー入力は主に DOS の INT 21h（AH=06h/07h/0Ch）。起動時に INT DCh
	  で f･1～10，SHIFT+f･1～10 に英字１文字（"LXCDRSFTEUAIMDKHWBVP"），
	  特殊キーに WordStar 風のコードを割り当てる
	    ROLL UP=03h ROLL DOWN=12h INS=16h DEL=07h ↑=05h ←=13h →=04h
	    ↓=18h HOME CLR=17h HELP=1Fh SHIFT+HOME CLR=1Ah
	・修飾キーは INT 18h AH=02h，キーマトリクスは AH=04h で直接調べる
	  （GRPH + 英字，CTRL + HOME CLR，NFER/XFER など）
	・コンソールには PC-98 の ESC シーケンスを出力する
	  （ESC[>1h/l，ESC[>3h/l，ESC[>5h/l，ESC[m，ESC[2J，ESC=rc など）

◆◆◆◆ ドライブの判定（ＳＪ）

	・INT 21h AH=52h から CDS をたどって、ドライブの属性と最終ドライブを
	  求める（CE37h～CFDEh）。CDS を持たない DOS 環境では使えない
	・PC-98 版では、接続ディスク（0000:055Ch）と DOS の DA/UA 表
	  （0060:006Ch）から、フロッピー，MO，固定ディスクを判定する
	  （D00Fh～D08Bh）


■■■■■ ３．パッチの系譜と方式

	オリジナル	FD Ver.2.32 for PC-9801（A.Idei 氏，1991）
	ＦＤ３０	Release.3.20（ARGON 氏，1992）
	ＳＪ		パッチＣ（1993-07）～RL，RO，RQ，RR，RV（1996）～
			ＳＪ（1997-12）（「城」氏）。
			どの版もＦＤ３０適用後からの差分

◆◆◆◆ 各パッチの方式

	オリジナル 2.32	暗号化はされていない
	ＦＤ３０	原版を 62 バイト書き換え，末尾に 1619 バイトを追加。
			先頭の jmp を追加部分に向け、起動時に本体のコードを
			書き換える（30 行対応）
	ＳＪ		ＦＤ３０の状態を再アセンブルしたもの。0E2Ah 以降の
			配置は原版と異なり、原版のコードは命令単位で約半分
	FMR 版		Yagisita 氏による FM-R50 への移植（1995）。原版を
			再アセンブルし、画面，キー，ファンクションキー，
			パレット，ビープ，GDC，Backup を FM-R の BIOS に置き
			換えたもの（命令の約 94% は原版と同じ）
	2.32SJ.M	ＳＪのバイナリはそのままに、FD.COM に模擬層を追加
			（５．参照）

　なお Ver.3.x の FD98.COM とローダーは、XOR による多段の自己復号で
保護されている（DOS/V 版の FD55.COM，FDPC.COM は保護なし）。


■■■■■ ４．機種による実装の違い（Ver.3.12/3.13 の調査）

　原作者による Ver.3.12/3.13 の PC-98 版（FD98），DOS/V 日本語版（FD55），
英語版（FDPC）を比較した結果です。

	・FD55 と FDPC はコードが同一で、メッセージ表（日本語／英語）だけが
	  異なる。DOS/V のローダーは INT 15h AX=4900h と INT 21h AH=63h で
	  日本語モードかを調べて、どちらかを起動する
	・FD98 と FD55/FDPC のコードの共通部分はおよそ８割（メッセージ文字列
	  を除いた比較）。共通のエンジン（ファイル操作，ソート，ディレクトリの
	  書き込み，アーカイバ，EMS ヒストリ，INT 25h/26h による直接アクセス）
	  に、機種依存の層を差し替えた構造。Ver.3.12 と 3.13 で機種依存部の
	  切り分けは変わらない

	機能		PC-98（FD98）			DOS/V（FD55/FDPC）
	--------------------------------------------------------------------
	画面		テキスト VRAM 直接		V-text
							（INT 10h AH=FEh/FFh）
			（JIS，属性面 +2000h）		（シフト JIS のまま）
	カーソル	INT 18h AH=11h/12h，		INT 10h
			INT DCh CL=10h
	キー		INT 18h AH=02h/04h，I/O 41h	INT 16h
							（待機中は INT 28h）
	登録コマンド	GRPH/NFER + A～Z		Alt + A～Z
	ﾌｧﾝｸｼｮﾝｷｰ	INT DCh CL=0Ch/0Dh で定義	FD が描画（10/12 個）
	背景色		グラフィック画面，		なし
			アナログパレット
	クリック音	I/O 37h				なし
	Backup		INT 1Bh				なし
	画面行数	20/25 行			V-text のモード指定
	色の設定	FD.CFG（8 色＋属性）		FDCUST が本体を書き換え
							（16 色×16 色）

　FD.DOC（3.12/3.13 共通）には、原作者による IBM と PC-9801 のキーの対応表が
ある（FDPC_SJM.DOC の４．２参照）。


■■■■■ ５．2.32SJ.M の実装

◆◆◆◆ ５．１  方針

	・FD98.COM の大きさと配置は変えない（ＳＪの自己サイズ確認，FDCUST2
	  の固定位置への書き込み，PC-98 版の FD.CFG がそのまま使える）
	・PC-98 の画面，キーボード BIOS，DOS コンソールを FD.COM の常駐部で
	  模擬し、FD98.COM の PC-98 用のコードをそのまま動かす
	・何をどのキー・機能に置き換えるかは、Ver.3.x の FD98 と FD55 の違い，
	  および FD.DOC のキー対応表に従う

◆◆◆◆ ５．２  FD.COM に追加した常駐部

　FD.COM はメモリを縮めたあと、模擬層（約 5.4KB）とシャドウ VRAM（16KB）の
ブロックを確保して、次のベクタをフックする。FD.COM の終了時に戻す。

	INT 09h		キーマトリクスの記録
	INT 18h		PC-98 キーボード／CRT BIOS の模擬（AT の INT 18h は
			ROM BASIC なので、元のベクタには渡さない）
	INT 21h		FD98 の EXEC の検出，FD98 からのコンソール入出力の
			模擬，FD.COM 終了時の後始末
	INT DCh		ファンクションキー定義（CL=0Ch/0Dh），カーソル位置
			（CL=10h AH=03h），模擬層の内部機能（CL=F0h：シャドウ
			VRAM のセグメント，CL=F1h：行数）
	INT DEh		I/O 41h（PC-98 キーボードデータ）の代わり
	INT DFh		ブザーの代わり（CX = 長さ）

　INT 21h の横取りは、FD98 の実行中で、子プロセスを実行しておらず、
現在の PSP が FD98 のもののときに限る（オーバーレイは別セグメントで動く
ため、CS ではなく PSP で判定する）。対象は AH=01h，02h，06h，07h，08h，
09h，0Bh，0Ch。

◆◆◆◆ ５．３  画面の模擬

	・シャドウ VRAM は PC-98 と同じ形式（文字面 0000h，属性面 2000h）
	・FD98 の VRAM セグメント変数にシャドウ VRAM を入れる
	・反映：シャドウ VRAM と V-text バッファを比べ、変化したセルだけを
	  変換して書き込み、INT 10h AH=FFh で更新する。反映するのは、キー
	  入力待ちの前（INT 21h，INT 18h），および FD98 が DOS を呼んだとき
	  （２ティック以上の間隔）
	・全角：JIS → シフト JIS。対になる右セルがないものは空白
	・半角：PC-98 の ANK 図形文字は DOS/V の半角罫線（二重線）などに
	  変換する（両機種で 256 文字を表示して対応を決めた）
	    PC-98			DOS/V（二重線）
	    95h ─			06h 横線
	    96h │			05h 縦線
	    98h～9Bh ┌┐└┘		01h～04h 左上，右上，左下，右下
	    9Ch～9Fh（角の丸い枠）	01h～04h
	    93h ├，92h ┤		19h，17h
	    91h ┬，90h ┴，8Fh ┼	16h，15h，10h
	    1Ch～1Fh →←↑↓		1Eh，1Fh，1Ch，07h
	・属性：色（GRB）は PC の明るい色（9～15）に。リバースは「明るい色の
	  背景＋背景色の文字」に（PC-98 ではリバースの文字の部分にグラフィ
	  ック画面の背景色が透ける）。属性の bit7 は DOS/V の V-text では
	  明るい背景色として扱われる（FD55 も同じ前提）。アンダーラインは
	  「その色の暗い背景＋明るい前景」に。ST=0 は前景色＝背景色。
	  背景色は FD.CFG の back，Green，Red，Blue（FD98.COM の 0E46h～
	  0E49h）から近い色を選ぶ
	・反映の範囲：変化のあった行の先頭から末尾までを INT 10h AH=FFh で
	  描き直す（全角文字の２バイト目だけが変わったときに、途中から描く
	  と半角として表示されるため）
	・カーソル：ESC[>5h/l と INT 18h AH=11h/12h は同じカーソルを切り替え
	  る（後から指定した方が有効）。INT DCh CL=10h AH=03h で位置を設定
	・コンソール：FD98 が DOS で出力した文字と ESC シーケンスを解釈して
	  シャドウ VRAM に書く（カーソル移動，消去，色，ESC[>5h/l など）。
	  ESC[>3h/l（20/25 行の切り替え）は、PC-98 のコンソールと同様に画面
	  を消去する（View の開始時に使われる。FD55 は同じ箇所で INT 10h の
	  全画面消去を行っている）
	・FD98 の起動時には実画面をシャドウ VRAM に読み込み（逆変換）、
	  外部コマンドの出力の上に "何かキーを押してください" が出るように
	  する。FD98 の終了時（終了コード 0，'C'）と子プロセスの実行前は、
	  Ver.3.x の DOS/V 版と同様に画面を消去する
	・行数：BIOS ワークエリア 0040:0084h から求め、25 行以外ならＳＪの
	  30 行対応の経路（D3B9h）に渡す

◆◆◆◆ ５．４  キーボードの模擬

	・INT 16h（拡張）で読んだキーを、PC-98 の DOS が返すコードに変換して
	  キューに入れる
	    F1～F10，Shift+F1～F10	INT DCh で FD98 が設定した文字列
	    特殊キー			INT DCh で設定されたコード
	      Page Down=ROLL UP，Page Up=ROLL DOWN，Ins，Del，矢印，
	      Home=HOME CLR，End/Shift+Home=SHIFT+HOME CLR，F11=HELP
	      （Ctrl を押したときの別のスキャンコードも同じキーとして扱う）
	    その他			文字コードのまま
	・INT 18h AH=02h：INT 16h AH=12h の状態から CAPS，GRPH（Alt），CTRL
	  を返す。SHIFT は INT 09h で記録したキーの状態から返す（NumLock が
	  オンのとき灰色キーと一緒に送られる「偽の Shift」（E0 2Ah）を BIOS
	  は Shift として数えるため、Home が Shift+Home になってしまう）
	・INT 18h AH=04h：INT 09h で押されているキーを記録し、AT のスキャン
	  コードを PC-98 のキーマトリクスに対応付けて返す。Alt → GRPH，
	  無変換 → NFER，変換 → XFER，Home/End → HOME CLR など
	・INT DEh：最後に押された／離されたキーの PC-98 スキャンコード
	  （View の連続スクロールなどの ESC 判定に使われる）

◆◆◆◆ ５．５  FD98.COM の書き換え（大きさは変えない）

	D764h	ハイレゾ判定 → VRAM セグメントにシャドウ VRAM を設定
	D2E3h	行数の判定（0000:0711h～，30 行 BIOS）→ DOS/V の行数
	D00Fh	ドライブ表の作成（0000:055Ch，0060:006Ch）→ INT 11h と
		IOCTL（4408h，4409h）で作成。A:，B: は台数によらずフロッピー
		として扱う（フロッピーが１台の PC の B: は A: と同じ装置の
		仮想ドライブ。取り外し可能ドライブの一覧に入れると、Windows
		の DOS 窓で外部コマンドの実行前後にＳＪがボリュームをロック
		／解除し、「ドライブ B: にフロッピーディスクを…」が出る）
	6DBCh	背景色の有無 → 常に「なし」（グラフィック画面の処理を省略）
	D82Bh，8E2Ch	EMS の初期化（ems40=1,2）：マップ可能ページの一覧
		（INT 67h AX=5800h）を 16 バイトの領域に読み、先頭がページ
		フレームの 4 ページであることを前提にしていた（PC-98 の
		EMM386 の返し方）。JEMM など通常メモリのページも返す DOS/V
		の EMS ドライバでは、ドライブ関係の変数（D1BBh まで）を壊し、
		FD98_SJ$，FD98_U2S を確保しなかった → AH=41h のページフレーム
		からフレームの 4 ページを作る（処理は 8E27h の書き換えで使わ
		れなくなった GDC のカーソル形状の領域 8E2Ch に置く）
	D9F8h	長いファイル名用の変換表（FD.COM の 7EBh から 7E58h バイト）
		を最大 8000h バイト読み、ちょうど 7E58h であることを確認して
		いた。DOS/V 版の FD.COM は後ろにシムがあり長いので、7E58h
		バイトだけ読む（読めないと「FD.COM の版が違います」で終了）
	67FEh～6864h，68A9h，BCC1h
		PC-98 の I/O ポートへの出力を削除（AT では割り込みコント
		ローラなどと重なるため）
	0FA7h，C225h	I/O 5Fh（ウェイト用ポート）を使った待ちループ →
		INT 15h AH=86h の時間待ち（HOME CLR 押し続け時の全マーク
		の間隔 0.1 秒，ディスクリセット後 50ms）
	6D67h	ブザー（I/O 37h）→ INT DFh
	58A2h，E001h	I/O 41h の読み取り → INT DEh
	8E27h	カーソル形状：GDC 直接 → BIOS 経由の経路
	B0C6h，6783h	ＳＪ自身の不具合の修正（PC-98 版でも起きる）：CD-ROM の
		読み込み（B0C1h，MSCDEX INT 2Fh AX=1508h）がエラーになると
		「読み込みエラー発生」（817Dh）を出し、「もう一度」で同じ
		レジスタのまま読み直す。ところがエラー表示の処理（91D4h）が
		DX（読むセクタ数）にメッセージのアドレス 93EAh を入れるため、
		約 77MB を読もうとして暴走した → 817Dh の呼び出しの前後で
		DX，ES，CX，BX を保存する処理を、実行されなくなった背景色の
		描画ルーチンのタイトル文字列の後ろ（6783h）に置く
	2164h	[B]ackup → "書込処理 不可能"
	ACAAh	フロッピーのボリュームラベル行での C/D/K → 通常の処理
	EB3Ch，EB6Dh，A9D0h，5D64h	ヘルプ中のキー名
	675Fh，1406h	タイトル（"+SJ.M"）。元の文字列（6E67h）は直後に別の
		文字列が続き延ばせないため、実行されなくなった背景色の
		描画ルーチン（6757h～）の領域に新しい文字列を置き、表示
		位置を１桁左（18 桁目）にして中央を保つ
	※初期化の処理の領域（D1B9h～）は、起動後に CD-ROM のパステーブル
	  などのデータ領域として再利用されるので、追加の処理は置かない

◆◆◆◆ ５．６  FD.COM の書き換え

	06EBh	BIOS ワークエリアの読み取り → 通常の 25 行モードの値
	06E8h，04FCh	INT DCh（ファンクションキーの保存／復元）を削除
	071Ch	初期化の最後 → 末尾に追加したインストーラ
	末尾	インストーラと模擬層


■■■■■ ６．差分ファイルの構成

　FDPC_SJM.BDF は BDIFF 1.28 で作成し、次の差分を順に格納している。

	FD.COM		オリジナル → ＦＤ３０		（BDIFF で作成）
	FD.COM		ＦＤ３０ → ＳＪ		（ＳＪの FD_SJ.BDF）
	FD.COM		ＳＪ → 2.32SJ.M		（BDIFF で作成）
	FD98.COM	オリジナル → 2.32SJ.M		（BDIFF で作成）
	FDCUST2.COM	オリジナル → ＳＪ		（BDIFF で作成）
	FD.CFG		オリジナル → ＦＤ３０		（BDIFF で作成）

　FD.COM はオリジナルとの違いが大きく、BDIFF が１回で差分を作れない
（"fail to re-sync"）ため、段階的に更新する形にしている。BUPDATE は各段階の
元ファイルの日付も照合するので、オリジナルのファイルの日付を変えないこと。
